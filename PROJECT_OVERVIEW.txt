1. PROJECT PURPOSE AND PROBLEM STATEMENT
================================================================================

1.1 Product Purpose
BRANDCHECKER AI (referred to in project specifications as BrandCompass AI / Brandchecker AI)
is an intelligent brand and content governance web platform. It establishes an automated,
explainable verification and review layer between content creation and public distribution.

The platform ingests and learns the comprehensive brand identity of an organization or
individual media channel (vision, strategic editorial pillars, communication tone,
terminology blacklist/whitelist, visual rules, and verified facts). When authors draft
new content (posts, articles, documents, captions, or campaign collateral), the platform
evaluates the draft against that specific brand's guidelines across nine weighted dimensions,
generates a 0–100% alignment score, highlights specific discrepancies with actionable
explanations, provides a side-by-side improvement workspace, and routes the submission
through a human-in-the-loop review and approval workflow.

1.2 Problem Statement
Modern enterprises, marketing agencies, and media creators publish high volumes of content
through decentralized teams, distributed freelancers, and generative AI drafting tools.
This operational velocity introduces several critical failure modes:
  - Inconsistent Brand Voice & Tone Drift: Content fails to match the expected formality,
    cadence, or attitude of the brand.
  - Factual & SLA Contradictions: Authors inadvertently make claims that contradict official
    legal Master Service Agreements, availability SLAs, or regulatory disclosures (e.g.
    promising "100% zero downtime forever" when legal SLA is 99.99%).
  - Prohibited Terminology & Hyperbole: Use of cheapening clickbait words, buzzwords, or
    aggressive sales language ("cheat code", "magic", "cheapest in the universe", "BUY NOW").
  - Content Pillar Drift: Producing collateral that fails to advance core strategic themes.
  - Misleading Promotional Promises: Unsubstantiated absolute statements and missing legal
    disclaimers (e.g. missing FDA dietary notices or FTC disclosures).
  - Pure Rejection Without Solutions: Traditional compliance filters reject content outright
    without explaining why it failed or how to fix it while preserving the author's intent.
  - Disconnected Governance Workflows: Lack of structured approval audit trails, internal
    review notes, and version history before publication.

BRANDCHECKER AI directly addresses these problems by providing:
  1. Multi-account brand isolation (never auditing content against the wrong brand).
  2. Explainable 9-dimension scoring with 10 detailed data points per detected issue.
  3. A side-by-side Content Improvement Studio with visual diffs and 1-click remedies.
  4. Role-based review and approval workflows with private internal notes and audit logs.
  5. Continuous governance insights identifying recurring errors and suggesting guideline
     updates over time.

4. INCOMPLETE, MOCKED, OR UNIMPLEMENTED FEATURES
================================================================================

To ensure complete accuracy, the following items describe how certain features are
currently architected versus production enterprise backends:

4.1 Client-Side Web Storage Persistence (No Remote PostgreSQL/Supabase Server)
- How it works currently: All data (accounts, content, reports, comments, notifications,
  and activity logs) is persisted in the browser via Web Storage (`localStorage`) and
  in-memory React Context (`src/lib/storage.ts`).
- What is not implemented: There is no live remote connection to a PostgreSQL instance or
  Supabase Cloud backend. Data changes persist within the same browser session and across
  refreshes on that machine, but clearing browser cache or opening an incognito window
  reverts to the initial seed data.

4.2 Simulated Authentication (No JWT / OAuth / Backend Session)
- How it works currently: The `/login` and `/signup` screens simulate authentication by
  updating the user profile in `localStorage` and switching the active role in `AppContext`.
- What is not implemented: There is no server-side password hashing (bcrypt/argon2),
  OAuth2 providers (Google/GitHub/SAML), email verification, password reset email delivery,
  or signed JWT session cookies.

4.3 Live Gemini API Network Call (Currently Uses Local Governance Engine)
- How it works currently: The `/settings` screen allows inputting a Gemini API key and
  saving it in local storage. The `analyzeContentWithBrandRules(input, apiKey?)` signature
  accepts the key, but executes the deterministic semantic governance rule engine locally.
- What is not implemented: The code does not currently invoke `@google/genai` or make an
  outbound fetch to Google's Generative Language REST endpoint (`https://generativelanguage.googleapis.com/...`).
  All evaluations, scoring, and diff suggestions are generated by the local rule-based
  algorithm.

4.4 Binary Document Text Extraction (PDF / DOCX Parsing)
- How it works currently: Uploading plain text files (`.txt`, `.md`) parses contents into
  the editor using `FileReader.readAsText()`. For binary `.pdf` and `.docx` files, the
  uploader records the filename and file size, but does not execute binary text extraction
  or OCR. Users paste or write the text in the editor.

4.5 Automatic Video Speech-to-Text Transcription
- How it works currently: The upload screen provides "YouTube" and "Video" content types,
  allowing users to paste video scripts or transcripts for analysis.
- What is not implemented: There is no automated audio extraction or Whisper-based speech-
  to-text service running on video binary files.

4.6 Computer Vision Analysis on Image Assets
- How it works currently: When an image file is attached, the engine sets `hasVisualAsset: true`
  and awards positive marks under Visual Consistency if text complies with formatting rules.
- What is not implemented: There is no pixel-level computer vision model analyzing image
  contrast ratios, color histogram percentages, or OCR logo bounding boxes from image files.

4.7 External Email & Slack Notifications
- How it works currently: Notifications are fully operational inside the application via
  the in-app bell dropdown.
- What is not implemented: No outbound SMTP email or webhook notifications (Slack/Teams)
  are dispatched.

5. COMPLETE END-TO-END USER JOURNEY
================================================================================

A standard end-to-end user journey through the platform proceeds as follows:

Step 1: Discovery & Platform Exploration
  - User visits the Landing Page (`/`).
  - Reads the governance problem statement, product preview, and 9-dimension framework.
  - Tests the interactive hero widget with sample copy to see instant issue detection.
  - Clicks "Start Protecting Your Brand" or "Sign In".

Step 2: Authentication & Persona Simulation
  - User navigates to `/login`.
  - Can enter custom credentials or click a 1-click persona button (e.g. Elena Rostova as
    ADMIN or Sophia Chen as CREATOR).
  - System loads the designated user state and redirects to `/dashboard`.

Step 3: Multi-Brand Portfolio Selection
  - User reviews active brand in the top navigation or sidebar.
  - Clicks Account Switcher dropdown or visits `/accounts` to switch between Nexus Cloud AI,
    Lumina Health, or Pulse Media Network.
  - Alternatively, clicks "Create New Account" to launch the 6-Step Onboarding Wizard (`/setup`)
    to configure a brand identity from scratch.

Step 4: Guideline & Knowledge Base Review
  - User navigates to `/guidelines` to inspect the active brand's rules.
  - Reviews vision boundaries, focus topics, content pillars, vocabulary blacklist,
    hex color standards, and verified company facts.
  - Can add new blacklisted buzzwords or verified facts with source citations and click
    "Save Revisions".

Step 5: Drafting & Uploading Content
  - Creator navigates to `/upload`.
  - Selects channel (e.g. LinkedIn), category (e.g. Product Announcement), intended audience,
    and enters a title.
  - Pastes draft copy into the editor or uploads a file.
  - Clicks "Analyse Content with AI".

Step 6: AI Governance Analysis & Issue Inspection
  - The governance engine audits the draft against the active brand's guidelines.
  - System redirects to the detailed report (`/reports/[id]`).
  - User reviews the overall alignment percentage (e.g. 54%) and circular gauge.
  - Inspects individual scores across all 9 dimensions.
  - Switches to the "Detected Issues" tab to examine each flagged violation with its
    10 data fields, guideline citations, and explanations.

Step 7: Remediation in the Content Improvement Studio
  - Creator clicks "Open in Improvement Studio" (`/studio?id=...`).
  - Compares original draft against AI-suggested brand-aligned copy using Side-by-Side
    or Inline diff modes.
  - Clicks "Accept & Apply Improvements" to adopt suggestions, or edits manually in the editor.
  - Clicks "Re-Analyse Content" to re-evaluate the revised text.
  - Watches score climb (e.g. from 54% to 88%), with the version timeline tracking lift.
  - Clicks "Submit for Review".

Step 8: Review & Approval Workflow
  - Reviewer/Manager switches persona to REVIEWER or visits `/approval`.
  - Opens the newly submitted item from the queue.
  - Inspects the revised copy, latest score (88%), and report.
  - Adds a private internal note or public review comment.
  - Clicks "Approve Content", adds an audit justification, and confirms.
  - Item status updates to `approved`, an in-app notification is dispatched, and the action
    is logged.

Step 9: Audit Trail, Analytics, & Continuous Improvement
  - Team visits `/history` to verify the item is recorded with full version timeline diffs.
  - Downloads complete records via "Export History (CSV)".
  - Visits `/analytics` to review recurring mistake patterns and inspect AI recommendations
    suggesting updates to brand guidelines.
  - Visits `/settings` to fine-tune scoring weights or AI configuration.

7. HOW AI CONTENT ANALYSIS WORKS IN THE CODEBASE
================================================================================

Content analysis is implemented in `src/lib/analysis-engine.ts` via the function
`analyzeContentWithBrandRules(input: AnalysisInput, apiKey?: string)`.

7.1 Analysis Pipeline Inputs
  - `content`: Raw text of the draft copy.
  - `title`: Content title.
  - `account`: Complete active `Account` object containing vision, strategy, communication
    identity, visual rules, and approved knowledge base facts.
  - `category`: Assigned editorial category.
  - `targetPlatform`: Publishing destination (LinkedIn, Twitter/X, Blog, etc.).
  - `intendedAudience`: Stated target demographic.
  - `hasVisualAsset`: Boolean indicating whether an image/asset was uploaded.

7.2 Multi-Vector Evaluation Logic Across the 9 Dimensions:

Dimension 1: Vision Alignment (Default Weight: 20%)
  - Scans content against `account.vision.avoidedTopics`.
  - If draft text matches 2+ significant words of an avoided topic or includes the phrase,
    it reduces the dimension score by 30 points and generates a CRITICAL issue
    (`Restricted Brand Topic Detected`).
  - Scans for keyword intersection with `account.vision.focusTopics`. If absent, deducts
    10 points. If present, records positive strengths.

Dimension 2: Content Pillar Alignment (Default Weight: 15%)
  - Extracts keyword stems from each approved pillar in `account.contentStrategy.pillars`.
  - If text fails to match at least 2 keywords from an approved pillar, deducts 25 points
    and flags a MEDIUM issue (`Ambiguous Content Pillar Categorization`).

Dimension 3: Tone & Voice (Default Weight: 15%)
  - Punctuation Cadence Check: Counts exclamation marks. If count > 2, deducts 25 points
    and generates a MEDIUM issue (`Inconsistent Brand Formality - Excessive Exclamation`),
    citing the brand's required formality level.
  - Capitalization Shouting Check: Regex scans for words in ALL-CAPS (3+ letters), excluding
    an industry acronym whitelist (API, SLA, SOC, CPU, GPU, VPC, IEEE, ISO, LLM, ROI,
    NAD, FDA, cGMP, LUT, DNS). If found, deducts 20 points and flags a HIGH issue
    (`Prohibited Capitalization Shouting`).

Dimension 4: Audience Relevance (Default Weight: 10%)
  - Matches content vocabulary against `account.contentStrategy.audienceInterests`.
  - If no resonance is detected, deducts 15 points.

Dimension 5: Factual Accuracy (Default Weight: 15%)
  - Evaluates statements against `account.approvedInformation.facts`.
  - Specific Rule: Detects false availability claims such as "100% zero downtime" or
    "zero downtime forever". If detected, deducts 40 points and flags a CRITICAL issue
    (`Contradiction of Verified SLA Fact`), citing the official contractual 99.99% SLA.

Dimension 6: Terminology Consistency (Default Weight: 5%)
  - Exact regex boundary scan against `account.communicationIdentity.avoidedWords`.
  - Deducts 25 points for each blacklisted term and generates a HIGH issue
    (`Prohibited Terminology`), citing the brand's restricted vocabulary rule.
  - Scans for `account.communicationIdentity.preferredVocabulary` and records strengths.

Dimension 7: Visual Consistency (Default Weight: 10%)
  - Evaluates whether an uploaded asset conforms to approved palette safe zones.

Dimension 8: Accessibility Standards (Default Weight: 5%)
  - Cognitive Sentence Length: Splits text into sentences. If any sentence exceeds 35 words,
    deducts 15 points and flags a LOW issue (`High Cognitive Load - Excessive Sentence Length`).

Dimension 9: Promotional Claim Compliance (Default Weight: 5%)
  - Scans for high-pressure sales phrasing: "buy now" (High), "only product you will ever need"
    (Critical), "cheapest" (High), "miracle" (Critical), and "overnight" (Medium).
  - Deducts 25 points per phrase and flags issues under promotional governance.

7.3 Score Normalization & Output Structure
- Each dimension score is clamped to the range [0, 100].
- The overall score is calculated as a weighted average using `calculateWeightedScore()`
  based on `account.scoringWeights`.
- A qualitative summary verdict and executive summary narrative are generated.
- `originalPurposeSummary` captures the author's intended message to ensure proposed
  corrections preserve communicative intent.
- Returns an `AnalysisReport` object stored in `localStorage` under `brandchecker_reports_v1`.

7.4 Improvement Generation Algorithm
- Implemented in `generateImprovedContent()`.
- Systematically replaces detected violations:
  - Removes all-caps shouting and aggressive emojis.
  - Replaces "magical cheat code that will effortlessly replace all your backend developers
    overnight" with deterministic multi-agent routing narrative.
  - Replaces "cheapest cloud solution... 100% zero downtime forever" with enterprise
    zero-trust VPC narrative backed by SOC 2 Type II, ISO 27001, and 99.99% SLA.
  - Replaces "fire your dev team" call-to-actions with technical whitepaper walkthrough links.
  - Substitutes blacklisted words with approved preferred terms.
